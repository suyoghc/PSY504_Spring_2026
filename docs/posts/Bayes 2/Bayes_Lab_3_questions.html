Bayesians have many kinds of distributions

In Bayesian statistics, we have at least 6 distributions to keep track of. Those are:

  • the likelihood distributions
  • the prior parameter distribution (aka priors)
  • the prior predictive distributions
  • the posterior parameter distributions (aka posteriors)
  • the posterior-predictive distribution

In many respect, it’s distributions ‘all the way down,’ with Bayesians. This can indeed be difficult to keep track of at first. But since this is true for any class of Bayesian models (not just regression), you’ll hopefully get used to it.

Likelihood distributions.

We are approaching Bayesian statistics from a likelihood-based perspective. That is, we situate regression models within the greater context of a likelihood function. (There are ways to do non-parametric Bayesian statistics, which don’t focus on likelihoods. We won’t get into that right now.)

So far, we have been using the conventional Gaussian likelihood. If we have some variable \(y\), we can express it as normally distributed by

\[ \operatorname{Normal}(y \mid \mu, \sigma) = \frac{1}{\sqrt{2 \pi \sigma}} \exp \left( \frac{1}{2} \left( \frac{y - \mu}{\sigma}\right)^2\right), \]

where \(\mu\) is the mean and \(\sigma\) is the standard deviation. With this likelihood,

  • \(\mu \in \mathbb R\)
    • the mean can be any real number, ranging from \(-\infty\) to \(\infty\)
  • \(\sigma \in \mathbb R_{> 0}\)
    • the standard deviation can take on any real number greater than zero.

It’s also the assumption

  • \(y \in \mathbb R\)
    • the focal variable \(y\) can be any real number, ranging from \(-\infty\) to \(\infty\).

One of the ways we wrote our model formula back in the first file was

\[ \begin{align} \text{bill\_length\_mm}_i & \sim \operatorname{Normal}(\mu_i, \sigma) \\ \mu_i & = \beta_0 + \beta_1 \text{body\_mass\_g}_i, \end{align} \]

and further in the discussion, we updated that equation with the posterior means for our three parameters to

\[ \begin{align} \text{bill\_length\_mm}_i & \sim \operatorname{Normal}(\mu_i, 2.92) \\ \mu_i & = 32.2 + 0.004 \text{body\_mass\_g}_i. \end{align} \]

Before we get into this, though, let’s back up and consider an intercept-only model of the form

\[ \begin{align} \text{bill\_length\_mm}_i & \sim \operatorname{Normal}(\mu_i, \sigma) \\ \mu_i & = \beta_0 , \end{align} \]

where there is no predictor variable. Here’s how to fit the model with brm().

Posterior-predictive distributions.

The gray band is the 95% interval for the entire posterior predictive distribution, not just the mean. In a good model, about 95% of the data points should be within those bands.

The jagged edges of the band reflect uncertainty in \(\sigma\), not just the mean.

You just did a posterior predictive check by hand — simulating datasets from the posterior and comparing their densities to the observed data. The pp_check() function automates this in one line:

Code

The dark line is the observed data density. The light lines are 100 simulated datasets from the posterior predictive distribution. If the model is good, the light lines should envelope the dark line.

Code

Code

The stat = "mean" check shows a histogram of posterior predictive means, with the observed mean as a vertical line. The stat = "sd" check does the same for spread. These targeted checks isolate whether the model captures specific features of the data.

Part 4: Beginning to look at priors

Bayes’ rule

Bayes’ theorem will allow us to determine the plausibility of various values of our parameter(s) of interest, \(\theta\), given the data \(d\), which we can express formally as \(\Pr(\theta \mid d)\). Bayes’ rule takes on the form

\[ \Pr(\theta \mid d) = \frac{\Pr(d \mid \theta) \Pr(\theta)}{\Pr(d)}. \]

where

  • \(\Pr(d \mid \theta)\) is the likelihood,
  • \(\Pr(\theta)\) is the prior,
  • \(\Pr(d)\) is the average probability of the data, and
  • \(\Pr(\theta \mid d)\) is the posterior.

We can express this in words as

\[ \text{Posterior} = \frac{\text{Probability of the data} \times \text{Prior}}{\text{Average probability of the data}}. \]

The denominator \(\Pr(d)\) is a normalizing constant, and dividing by this constant is what converts the posterior \(\Pr(\theta \mid d)\) into a probability metric.

Prior predictive checks

Every model makes predictions. Most of the time we think about predictions after fitting — but a model with priors is already making predictions before it sees a single data point. If those predictions are absurd, no amount of data will fully rescue the analysis. A quick check now saves you from trusting results that were compromised from the start.

We can do this by fitting the model with sample_prior = "only", which tells brms to ignore the data entirely and just simulate from the priors and likelihood:

Code 
fit_prior_only <- brm(
  data = chinstrap,
  bill_length_mm ~ 1 + body_mass_g,
  prior = prior(normal(0, 0.01), class = b),
  sample_prior = "only"
)

Note: we had to set an explicit prior on the slope (class = b) because the default flat prior can’t be sampled — it spans \(-\infty\) to \(\infty\). We used normal(0, 0.01), which is a reasonable weakly informative prior for this scale.

Now run pp_check() on the prior-only model:

Code 
pp_check(fit_prior_only, ndraws = 50)

pp_check() overlays your observed data (dark line) as a reference, but the evaluation here is different from a posterior predictive check. The light lines are datasets the model would generate using only the priors — no learning from data at all. You’re not asking “do these match my data?” (priors that already reproduce the data would be suspiciously informative). You’re asking “are these physically plausible for penguin bill lengths?” Predictions in the 30–60 mm range are reasonable. Predictions spanning hundreds of millimeters mean the priors are encoding implausible assumptions.

Model comparison with LOO-CV

In your MLM unit, you compared models with AIC and BIC. The Bayesian analog is Leave-One-Out Cross-Validation (LOO-CV).

The idea: hide one data point, fit the model on the remaining 67, and predict the held-out point. Repeat for every point. Models that predict held-out data well are capturing real structure; models that predict poorly are either too simple or fitting noise.

Rather than actually refitting the model 67 times, loo() approximates the cross-validation using your existing posterior draws. It estimates how much each data point influenced the fit. Points the model already predicts well had little influence; points that surprised the model — the ones that would have been flagged as unusual in a residual plot — had a lot. Averaging across all points gives you an overall score for how well the model predicts new data. So a model that is consistently unsurprised by held-out points gets a high score, and one that is frequently caught off guard gets a low one.

The key number in the output is ELPD (expected log pointwise predictive density). Higher ELPD = better out-of-sample prediction. When comparing two models, loo_compare() puts the better model on top and reports the difference with a standard error. A difference many times larger than its SE is reliable.

Code 
loo0 <- loo(fit0.b)
loo1 <- loo(fit1.b)
loo_compare(loo0, loo1)
       elpd_diff se_diff
fit1.b  0.0       0.0   
fit0.b -9.2       3.7

The first row is the better model. The elpd_diff column tells you how much better, and se_diff tells you how certain that difference is.
