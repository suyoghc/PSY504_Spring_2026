The Case for Bayesian MLM

Where we are

You already know two things:

  • How to fit mixed models with lmer(): random intercepts, random slopes, crossed effects, ICC, model comparison

  • How to fit Bayesian regression with brm(): priors, posteriors, credible intervals, posterior predictive checks, LOO-CV

Today: what happens when we combine them

What does lme4 actually do?

lme4 uses a procedure equivalent to empirical Bayes:

  • Estimate the variance components via ML or REML (REML is the lmer default)
  • Fix those at plug-in estimates as if they were known
  • Condition on them to get the random effects (BLUPs)

The uncertainty in the variance components is not propagated to the group-level estimates.

A frequentist proof that pooling wins

In 1956, Charles Stein proved something that surprised the statistics world:

  • If you’re estimating three or more group means at once, estimating each one separately is always beatable
  • An estimator that pulls groups toward each other will have lower prediction error, on average
  • Pulling groups toward each other is not a Bayesian idea. It has frequentist proofs.

lmer() already produces these pulled estimates (shrinkage). The Bayesian model does the same pulling, with full uncertainty about how much to pull.

The right tool for the job

Simple balanced experiment

Using Bayes to analyze a clean 2x2 ANOVA is like cutting a birthday cake with a chainsaw.

It works, but the extra machinery does nothing.

Multilevel models

Fitting hierarchical models without Bayes is like cutting down a tree with a pocketknife.

It works, but you end up making compromises you don’t have to make.

Bayes vs. freq differences are more striking with MLMs.

The Pooling Framework

Complete pooling

  • One grand estimate: ignores groups entirely
  • Pro: simple, uses all data
  • Con: misses group-level variation

No pooling

  • Each group estimated independently from its own data
  • Pro: captures group uniqueness
  • Con: limited by each group’s sample size; overfits small groups

Partial pooling

  • Groups borrow strength from each other
  • Small groups have more sampling error; borrowing reduces it
  • The amount of borrowing is learned from the data

The group-level standard deviation controls pooling

The hyperparameter \(\sigma\) (group-level SD) determines the amount of pooling:

  • \(\sigma\) close to 0: groups are nearly identical, recover complete pooling
  • \(\sigma\) very large: groups are essentially independent, recover no pooling
  • \(\sigma\) estimated from data, guided by your prior on \(\sigma\)

You do not hand-pick the amount of pooling. The model estimates it from the data, guided by your prior on \(\sigma\).

The duck-rabbit

(a) A description of population structure

Groups come from a population. The model describes that population’s distribution.

(b) A regularization machine

Extreme estimates from small groups get pulled toward the population average.

If you model the population, regularization happens.

If you want regularization, model the population.

What is shrinkage?

Partial pooling produces shrinkage: estimates pulled toward a common value.

  • Groups with few observations shrink more toward the grand mean
  • Groups with many observations retain their individual character
  • Groups with extreme raw estimates get pulled further

Adaptive, automatic, and not a tuning choice.

Three Models in brms

The radon data

EPA measurements of radon gas levels in 919 Minnesota homes across 85 counties.

Radon data: key variables

  • Outcome: log_radon (log of radon gas level)
  • Predictor: floor (0 = basement, 1 = first floor)
  • Grouping: county (85 Minnesota counties)
  • County-level: log_uranium (soil uranium content)

Model 1: Complete pooling

Ignore counties entirely. One regression for all 919 homes.

fit_pool <- brm(
  log_radon ~ floor,
  data = mn_radon,
  file = "fits/fit_pool"
)
fixef(fit_pool)

Intercept  1.3625440 0.02884281  1.3072374  1.4198890
floor     -0.5873097 0.06960242 -0.7211983 -0.4532058

Model 2: No pooling

Each county gets its own intercept, estimated from its own data. (The floor slope and residual variance are still shared.)

fit_nopool <- brm(
  log_radon ~ 0 + floor + county_id,
  data = mn_radon,
  file = "fits/fit_nopool"
)

Model 3: Partial pooling

Counties share a common distribution. Each county’s estimate borrows strength from the others.

fit_partial <- brm(
  log_radon ~ floor + (1 | county_id),
  prior = prior(normal(0, 1), class = Intercept) +
    prior(exponential(1), class = sd) +
    prior(exponential(1), class = sigma),
  data = mn_radon,
  file = "fits/fit_partial"
)

The formula is the same as lmer(): (1 | county_id)

The one addition: prior(exponential(1), class = sd)

Syntax (lme4 vs. brms)

lmer() and brm(): same formula

Formula
lmer() mean_pupil ~ vocoded + (1 + vocoded \| subject)
brm() mean_pupil ~ vocoded + (1 + vocoded \| subject)
What changes Add prior(exponential(1), class = sd)

The formula syntax is identical. The difference is that brms puts an explicit prior on \(\sigma\) (the group-level SD), while lme4 fixes it at a plug-in estimate.

ranef() vs. coef() in brms

Two ways to summarize group-level parameters:

  • ranef() (random effects, or “group-level effects” in brms) returns deviations around the grand mean (\(u_{0i}\))
  • coef() (coefficients, or “population-level + group-level” in brms) returns the actual group intercepts (\(\beta_0 + u_{0i}\))
# Deviations from grand mean
ranef(fit_partial)

# Actual county-level intercepts
coef(fit_partial)

Testing and Practical Workflow

HDI-based significance

Does the 95% credible interval for a fixed effect exclude zero?

posteriors <- as_draws_df(fit_partial)

hdi(posteriors$b_floor, ci = 0.95)
95% HDI: [-0.79, -0.53]

If the HDI excludes zero, the effect is credibly different from zero at 95%.

Posterior predictive check

pp_check(fit_partial, ndraws = 100) +
  theme_bw(base_size = 18)

Building hierarchical models incrementally

McElreath’s practical workflow:

  1. Start with intercepts-only: y ~ 1 + (1 | group)
  2. Run prior predictive checks on the hierarchical structure
  3. Fit and check diagnostics (ESS, Rhat, especially for \(\sigma\))
  4. If you see divergences, increase adapt_delta (e.g., control = list(adapt_delta = 0.95))
  5. Prior-posterior overlap for \(\sigma\) is common and expected — data often cannot fully learn the variance structure
  6. Add varying slopes if theoretically motivated

Watch for these diagnostics

Diagnostic What it tells you Worry threshold
Rhat Chain convergence Above 1.01
Bulk ESS Posterior body sampling Below 400
Tail ESS Posterior tail sampling Below 400
Divergences Funnel geometry problems Any above 0

Divergences in hierarchical models often mean the sampler is struggling with the “funnel” shape of the posterior where \(\sigma\) is small.

Optional: Bayes Factors for Parameter Testing

Testing parameters with Bayes Factors

Can we test whether a specific effect is zero?

  • Use bayesfactor_parameters() from bayestestR
  • Requires sample_prior = "yes" and an explicit prior
# Fit with prior sampling enabled
fit_bf <- brm(
  log_radon ~ floor + (1 | county_id),
  prior = prior(normal(0, 1), class = Intercept) +
    prior(normal(0, 1), class = b) +
    prior(exponential(1), class = sd) +
    prior(exponential(1), class = sigma),
  data = mn_radon,
  sample_prior = "yes",
  file = "fits/fit_bf"
)

# Test floor effect against zero
bayesfactor_parameters(fit_bf, null = 0)
